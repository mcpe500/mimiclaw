## 3. Gate Specifications

### Gate availability on Termux

| Gate | Termux | Notes |
|------|--------|-------|
| RED (write tests) | YES | |
| ANALYZE (cppcheck) | YES | clang-tidy blocked |
| ASAN | YES | |
| VALGRIND | NO | Android blocks ptrace |
| FUZZ | NO | libFuzzer unavailable |
| COVERAGE | YES | gcov/lcov |
| TEST | YES | unit + integration |
| REGRESSION | PARTIAL | test+analyze+asan+coverage |
| IDF.PY BUILD | NO | requires x86_64 |

### Gate outcomes
- `pass` — gate ran, 0 errors
- `fail` — gate ran, errors found
- `blocked` — gate could not run (tool missing)

## 5. Results Logging

File: `~/mimiclaw/results.tsv`

```
commit	feature	tests_total	tests_pass	static_warns	asan_errors	valgrind_errs	fuzz_crashes	coverage_pct	status	description
```

Status values: done, discard, crash, blocked

Use `blocked` when:
- ESP-IDF missing
- valgrind unavailable
- fuzz toolchain unavailable
- tool missing

## 6. Development Loop

```
LOOP F1 → F23:
  0. Preflight: cd ~/mimiclaw && git status
  1. Pick next unfinished feature
  2. Read spec + source files
  3. git pull && git checkout dev/<tag>
  4. Write tests FIRST (must FAIL)
  5. ANALYZE: make analyze
  6. Implement in main/
  7. ASAN: make asan
  8. VALGRIND: blocked (log it)
  9. FUZZ: blocked (log it)
  10. COVERAGE: make coverage
  11. TEST: make test
  12. REGRESSION: make full
  13. Commit + push
  14. Log to results.tsv
```

After backlog complete:
- Re-visit crashed/blocked features
- Final regression pass
- Report completion

---

## 7. Per-feature Timeout

~10-30 min per feature. If >2 hours, mark `crash` or `blocked` and move on.
