# Handoff & Progress Report - MimiClaw

## 1. Current Status

The project runs on two targets: ESP32-S3 (firmware) and host (Linux/macOS/Termux/Docker). The host target is the primary focus for the OpenClaw-like experience.

### 1.1 Host Product Runtime (`core/`)
- **Status**: Core product runtime built. Setup wizard + config system + HTTP client + message bus implemented.
- **User Experience**: Run `./mimiclaw` → first-time setup wizard (choose provider, enter API key, configure channels) → connects to Discord/Telegram/Slack/WhatsApp → runs autonomously.
- **What works**: Config load/save (JSON), setup wizard (interactive CLI), libcurl HTTP client, pthread message bus, graceful signal handling.
- **What's TODO in main.c**: Wire up channel init/start calls, agent loop start, WebSocket server start, admin UI start.

## 3. Architecture

```
User runs: ./mimiclaw
  │
  ├─ First run? → Setup Wizard (CLI)
  │   ├─ Choose LLM provider (Anthropic/OpenAI)
  │   ├─ Enter API key
  │   ├─ Configure channels (Discord, Telegram, Slack, WhatsApp)
  │   └─ Save to ~/.mimiclaw/config.json
  │
  ├─ Load config.json
  ├─ Init message bus (pthread)
  ├─ Init tools (registry)
  ├─ Init memory (filesystem)
  ├─ Start channels (each in own pthread)
  │   ├─ Telegram: HTTP polling via libcurl
  │   ├─ Discord: WebSocket Gateway + REST
  │   ├─ Slack: Socket Mode + REST
  │   ├─ WhatsApp: Cloud API polling
  │   └─ WebSocket: local WS server for chat UI
  ├─ Start agent loop (main thread)
  └─ Ctrl+C → graceful shutdown
```
